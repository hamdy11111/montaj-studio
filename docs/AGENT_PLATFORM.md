### 1.2 ما يُحافَظ عليه وما يُطوَّر

- **يُحافَظ عليه كما هو:** نموذج المشروع، والأوامر النقية، والتصدير، وقاعدة البيانات، والخدمات. هي مستقرة ومختبرة، وإعادة بنائها بلا مبرر.
- **يُضاف فوقها:**
  - طبقة **Editing API** موحّدة (كتالوج عمليات مكتوبة بمخططات)؛
  - **محرك المهارات**؛
  - **خادم تحكم محلي** بصلاحيات؛
  - **خادم MCP**.
- **قيد معماري حاسم:** حالة الخط الزمني والتاريخ تعيش في ذاكرة العملية الرئيسية. لو فتح خادم MCP مستقل قاعدة البيانات نفسها لعمل على حالة قديمة، ولكتب فوق تعديلات المستخدم دون أن يعلم. **لذلك لا يملك خادم MCP محركًا ثانيًا؛ هو جسر رقيق إلى التطبيق الذي يعمل.**

### 1.3 المخاطر والتبعيات

| الخطر | المعالجة |
|---|---|
| وكيل يكتب فوق عمل المستخدم | محرك واحد، و`revision` لكل خط زمني، و`expectedRevision` اختياري، وكل تنفيذ مهارة خطوة تراجع واحدة |
| وكيل يقرأ أو يكتب ملفات خارج نطاقه | صندوق مسارات: الاستيراد من جذور مسموحة فقط، والتصدير إلى مجلد مسموح فقط |
| مهارة خارجية خبيثة | المهارة بيانات تعريفية فقط (JSON مُتحقَّق بمخطط). لا كود قابل للتنفيذ. الخطوات تستدعي عمليات من قائمة سماح. المهارات الخارجية معطّلة حتى يفعّلها المستخدم |
| حقن تعليمات من محتوى الوسائط | لا يُعامَل أي نص من الوسائط أو الكابشن أو البيانات الوصفية كتعليمات. النتائج تُعاد كبيانات منظّمة، ولا توجد أداة «نفّذ هذا النص» |
| عمليات مدمّرة | نطاق `delete` منفصل لا يُمنح افتراضيًا، وموافقة المستخدم داخل التطبيق لكل عملية |
| الاعتماد على الإنترنت | كل شيء محلي: المهارات، والتحليل، وMCP عبر stdio وأنبوب محلي |

## 2. البنية المستهدفة

```
External Agent (Claude Code / Codex / أي عميل MCP)
   │  MCP عبر stdio (JSON-RPC)
   ▼
montaj-mcp  (src/mcp/server.mjs — عملية Node مستقلة، بلا حالة)
   │  JSON-RPC عبر Named Pipe محلي  +  Bearer token
   ▼
Agent Control Server  (src/agent/controlServer.js — داخل عملية Electron الرئيسية)
   │  المصادقة ← الصلاحيات (scopes) ← نطاق المشاريع ← صندوق المسارات ← حدّ المعدّل ← الموافقات ← سجل التدقيق
   ▼
Editing API — كتالوج العمليات  (src/agent/operations.js)
   │                                   ▲
   ├── Skills Runtime (src/agent/skills/runtime.js) ── Skill Registry (registry.js) ── Skill Schema
   ├── Jobs (src/agent/jobs.js): مهام طويلة، تقدّم، إلغاء
   ▼
Services الحالية: TimelineService (أوامر + تاريخ) · MediaService · AnalysisService · ExportService · ProjectService
   ▼
Realm (مصدر الحقيقة)
```

**مبادئ التصميم:**
- **مسار واحد للتعديل:** الواجهة اليدوية، و«المونتير الذكي» داخل التطبيق، والوكلاء الخارجيون كلهم يستدعون الخدمات نفسها. التعديلات تظهر في الخط الزمني فورًا، وتُعدَّل يدويًا، ويُتراجَع عنها.
- **عمليات مكتوبة لا نصوص حرّة:** لكل عملية مخطط مدخلات (JSON Schema) ونطاق صلاحية ووصف.
- **غير إتلافي:** لا تُعدَّل ملفات المستخدم الأصلية أبدًا. التصدير يكتب ملفات جديدة فقط.

## 3. Editing API — كتالوج العمليات ✅

العملية الواحدة: `{ name, title, description, scope, input (JSON Schema), run(ctx, args) }`. الكتالوج نفسه يغذّي أدوات MCP ومحرك المهارات. الأسماء:

| النطاق (scope) | العمليات |
|---|---|
| `read` | `project_list`، `project_inspect`، `timeline_inspect`، `media_list`، `media_inspect`، `skills_list`، `skills_inspect`، `skills_validate`، `skills_build_from_text`، `job_status`، `export_status` |
| `media` | `media_import` (مسارات مسموحة فقط)، `media_detect_silence`، `media_detect_scenes`، `media_loudness` |
| `edit` | `project_create`، `timeline_add_clip`، `timeline_split`، `timeline_trim`، `timeline_move`، `timeline_remove_clips`، `timeline_update_clips`، `timeline_add_layer`، `timeline_set_transition`، `timeline_transition_all`، `timeline_remove_ranges`، `timeline_set_canvas`، `timeline_undo`، `timeline_redo` |
| `skills.run` | `skills_execute` (ويُطلب معها نطاقات المهارة نفسها) |
| `skills.write` | `skills_save` (مهارة مستخدم جديدة أو إصدار جديد) |
| `export` | `export_start`، `export_cancel` (المخرج إلى مجلد التصدير المسموح فقط) |
| `delete` | `project_trash` (يتطلب موافقة المستخدم في كل مرة) |

**الأخطاء:** `{ code, messageKey, details }`، والرموز هي: `VALIDATION`، `NOT_FOUND`، `FORBIDDEN`، `CONFLICT`، `RATE_LIMITED`، `DENIED`، `MEDIA`، `PROVIDER`، `INTERNAL`.

**التزامن:**
- كل خط زمني يحمل `revision` يزيد مع كل تعديل.
- أي عملية تعديل تقبل `expectedRevision`. إن اختلف تُرفض بـ `CONFLICT` ولا يُكتب شيء.

## 4. محرك المهارات (Skills Engine) ✅ (المرحلة الأولى)

### 4.1 المواصفة
`src/agent/skills/skill.schema.json` (JSON Schema 2020-12). المهارة **بيانات فقط**:

| الحقل | المعنى |
|---|---|
| `id` و`name` و`description` و`version` (semver) و`author` و`source` | الهوية |
| `trust` | `official` أو `user` أو `external` |
| `category` و`tags` و`goals` و`capabilities` | الاكتشاف |
| `inputs` | خصائص JSON Schema مع قيم افتراضية؛ تُعرض للوكيل كما هي |
| `outputs` | وصف ما تُنتجه |
| `permissions` | النطاقات التي تحتاجها (مثل `edit`، `media`، `export`) |
| `requires` | `{ app, providers }`: أدنى إصدار للتطبيق، ومزوّدات مطلوبة مثل `whisper` (نموذج الكلام المحلي) |
| `dependsOn` | مهارات أخرى بإصداراتها، للتركيب |
| `settings` | قيم أسلوب تملكها المهارة (مثل `audio.loudness`)، تُقرأ في الخطوات عبر `{{settings.<key>}}`؛ في التركيب تغلب قيمة المهارة الأم |
| `steps` | خطوات بالترتيب. كل خطوة: `{ id, title?, op \| skill, with, when?, onError: fail\|skip }` |
| `success` | فحوص بعد التنفيذ: `timeline_not_empty` و`duration_reduced` و`duration_unchanged` و`has_captions`؛ فشل أيٍّ منها يُلغي المهارة كلها |
| `rollback` | `restore` افتراضيًا: إعادة الخط الزمني إلى ما قبل المهارة عند أي فشل |
| `tests` | حالات قبول **موصوفة** (المدخلات والنتيجة المتوقعة). لا يوجد بعد مُشغّل يقرؤها تلقائيًا؛ الاختبار الفعلي للمهارات الرسمية في `tests/unit/agents.test.js` ⏳ |
| `examples` | أمثلة استخدام |
| `integrity` | بصمة SHA-256 للمحتوى |

**القوالب في `with`:** `{{inputs.x}}`، و`{{steps.<id>.result...}}`، و`{{settings.<key>}}`، و`{{ctx.timelineId}}` و`{{ctx.durationUs}}` و`{{ctx.mainClipCount}}` و`{{ctx.hasCuts}}` و`{{ctx.revision}}`. الشرط `when` مرجع واحد من هذه (مع `!` للنفي). القيم تُستبدل بيانات فقط، ولا يوجد تقييم تعابير ولا تنفيذ كود.

### 4.2 Skill Registry ✅
- **المصادر:**

  | المصدر | الثقة | الحالة الافتراضية |
  |---|---|---|
  | مهارات رسمية (`src/skills/*.skill.json`) | `official` | مفعّلة |
  | مهارات المستخدم (`userData/skills/<id>/<version>.json`) | `user` | مفعّلة |
  | مهارات مستوردة | `external` | **معطّلة** حتى يفعّلها المستخدم |
- **الوظائف:** تسجيل، بحث وتصفية، تفعيل وتعطيل، إصدارات متعددة لكل مهارة، أحدث إصدار متوافق، فحص التبعيات ومنع الحلقات، تصدير واستيراد، وسجل تعديلات (`history.jsonl`).

### 4.3 التشغيل (Runtime) ✅
1. **التحقق:** تُتحقَّق المدخلات بالمخطط.
2. **الصلاحيات:** يُشترط أن تكون نطاقات المهارة ضمن نطاقات العميل.
3. **المتطلبات:** يُتحقَّق من العمليات والمزوّدات المطلوبة.
4. **التنفيذ:** تُنفَّذ الخطوات بالترتيب، وتُشارَك نتائج التحليل بين الخطوات عبر `steps.<id>.result`.
5. **النتيجة:**
   - **نجاح:** كل تعديلات المهارة تُدمج في **خطوة تراجع واحدة** باسم `skill:<id>`.
   - **فشل:** تُستعاد الحالة كاملة، ويُعاد سبب الفشل والخطوة.
6. **التتبّع:** كل تنفيذ مهمة (Job) لها معرّف وحالة وتقدّم، وتقبل الإلغاء.

### 4.4 التركيب ✅ (أساسي)
- تستطيع خطوة أن تستدعي مهارة أخرى (`skill`)، مع فحص الحلقات وحدّ للعمق.
- يُرفض التركيب إن تعارضت مهارتان على مفتاح الإعداد نفسه، مثل نسبتي عرض مختلفتين. التعارض يُعاد كخطأ `CONFLICT` صريح، ولا يُطبَّق أحدهما بصمت.
- إن ضبطت المهارة الأم المفتاح نفسه فقيمتها هي المعتمدة، وتصل فعلًا إلى خطوات المهارات الفرعية عبر `{{settings.<key>}}`. مثال مُختبَر: `podcast-cleanup` وحدها تضبط الصوت على −16 LUFS، وداخل مهارة أم تضبط −20 تضبطه على −20.

### 4.5 Skill Builder 🟡
- `skills_build_from_text` يحوّل وصفًا عربيًا أو إنجليزيًا إلى مسودة مهارة صالحة للمخطط، بقواعد محلية (توسعة لمحلّل EditPilot).
- لا يحفظ المسودة. الحفظ عبر `skills_save` بعد المراجعة.
- النموذج اللغوي اختياري لاحقًا عبر طبقة المزوّدات (⏳).

## 5. Agent Control Server والأمان ✅

- **النقل:**
  - أنبوب مسمّى محلي `\\.\pipe\montaj-studio-<user>`. لا شبكة، و**معطّل افتراضيًا**، ويفعّله المستخدم من الإعدادات.
  - رسائل JSON-RPC محدّدة الطول.
- **المصادقة:**
  - لكل عميل رمز سرّي يُعرض مرة واحدة عند إنشائه.
  - يُخزَّن تجزيئه (SHA-256) فقط في `userData/agents/clients.json`.
  - إلغاء العميل فوري.
- **التفويض:**
  - **النطاقات:** نطاقات العميل الافتراضية `read` فقط. ما بعدها (`media`، `edit`، `skills.run`، `skills.write`، `export`، `delete`) يُمنح صراحةً.
  - **المشاريع:** قائمة اختيارية بالمشاريع المسموحة.
- **صندوق المسارات:**
  - `media_import` مقصور على جذور يحدّدها المستخدم لكل عميل؛ يُستعمل `realpath` ويُمنع الخروج من الجذور.
  - التصدير إلى مجلد التصدير الخاص بالعميل أو الافتراضي فقط.
- **الموافقات:** عمليات نطاق `delete` (حاليًا `project_trash` فقط) تطلب موافقة المستخدم في نافذة داخل التطبيق تبقى فوق أي نافذة أخرى. الإغلاق أو مرور دقيقتين = رفض، وإن لم تكن هناك نافذة يُرفض الطلب. لا توجد عملية لاستبدال الملفات الأصلية أو حذفها.
- **حدود الاستخدام:** 20 طلبًا في الثانية لكل عميل (رصيد أقصى 40)، وحجم رسالة أقصى 1 MB.
- **سجل التدقيق:** `userData/agents/audit.jsonl` يسجّل الوقت، والعميل، والعملية، وملخّص المدخلات (المسارات تُختصر إلى اسم الملف)، والنتيجة أو رمز الخطأ، والمدة، و`revision` بعد التعديل. يُعرض آخره في الإعدادات › الوكلاء وMCP.

## 6. خادم MCP ✅

- **التشغيل:** `src/mcp/server.mjs` باستخدام `@modelcontextprotocol/sdk` 1.32.0 الرسمي، عبر **stdio**.
- **الأدوات:**
  - تُبنى ديناميكيًا من كتالوج العمليات (الاسم والوصف ومخطط المدخلات)، ويُعرض منها فقط ما يسمح به نطاق العميل.
  - كل مهارة مفعّلة تُعرض أيضًا كأداة `skill__<id>` بمخطط مدخلاتها.
- **الموارد:**

  | العنوان | المحتوى |
  |---|---|
  | `montaj://projects` | المشاريع |
  | `montaj://project/{id}` | مشروع واحد |
  | `montaj://timeline/{id}` | خط زمني |
  | `montaj://skills` | المهارات |
  | `montaj://skill/{id}` | مهارة واحدة |
  | `montaj://audit/recent` | آخر سجلات التدقيق |
- **القوالب (Prompts):** `edit_with_skill` و`build_skill`.
- **الاتصال:**
  - يقرأ الرمز من ملف `MONTAJ_TOKEN_FILE` (أو `MONTAJ_TOKEN`)، وعنوان الأنبوب من `<MONTAJ_USER_DATA>/agents/endpoint.json` (أو `MONTAJ_PIPE`).
  - يُشغَّل بملف التطبيق التنفيذي نفسه في وضع Node (`ELECTRON_RUN_AS_NODE=1`)، فلا يحتاج المستخدم إلى تثبيت Node.
  - إن لم يكن التطبيق يعمل، يعيد خطأ واضحًا. التشغيل التلقائي للتطبيق مخطط (⏳).
- **HTTP (Streamable HTTP):** ⏳ معطّل ولم يُبنَ. لن يُفعَّل إلا بمصادقة وTLS محلي.

## 7. الواجهة داخل التطبيق ✅

- **الإعدادات › الوكلاء وMCP:**
  - تشغيل الخادم المحلي وإيقافه (معطّل افتراضيًا).
  - إنشاء عميل: الاسم، والصلاحيات، والمشاريع (كلها أو ما ينشئه فقط)، ومجلدات الاستيراد، ومجلد التصدير. يُعرض الرمز مرة واحدة.
  - لكل عميل زر «الإعداد» يعرض أمر Claude Code وإعداد Codex وإعداد JSON لأي مضيف MCP آخر، مع زر نسخ. الرمز لا يظهر في الأمر، بل يُقرأ من ملفه.
  - إلغاء الوصول، وعرض آخر نشاط للوكلاء.
- **لوحة «المهارات» في المحرر:**
  - تشغيل أي مهارة مفعّلة على الخط الزمني الحالي بخياراتها، مع تقرير الخطوات والمدة قبل وبعد، وزر تراجع.
  - إنشاء مهارة من وصف نصي، مع عرض ما فُهم وما لا يمكن تنفيذه، ثم الحفظ.
  - استيراد مهارة (تبقى معطّلة حتى تُفعَّل) وتصديرها وحذفها.
- **تحديث حيّ:** حين يعدّل وكيل الخط الزمني المفتوح، يتحدّث المحرر فورًا مع إشعار باسم الوكيل، ويستطيع المستخدم التراجع عن تشغيل المهارة كله بـ Ctrl+Z. وتظهر المشاريع التي ينشئها الوكيل في الصفحة الرئيسية دون إعادة فتحها.
- **نافذة الموافقة:** تعرض اسم الوكيل والإجراء واسم المشروع، مع «سماح» و«رفض».

## 8. ربط Claude Code وCodex

1. افتح مونتاج ستوديو › الإعدادات › الوكلاء وMCP، وفعّل «السماح للوكلاء المحليين».
2. أنشئ عميلًا واختر صلاحياته ومجلداته.
3. انسخ من «الإعداد»:
   - **Claude Code:** الأمر `claude mcp add montaj-studio --scope user --env … -- "<Montaj Studio.exe>" "<…>/src/mcp/server.mjs"`.
   - **Codex:** الجزء `[mcp_servers.montaj-studio]` إلى `~/.codex/config.toml`.
4. يجب أن يكون التطبيق مفتوحًا أثناء عمل الوكيل.
